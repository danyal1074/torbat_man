# نگاشت نیازمندی‌های مسترپرامپت v3

سند پیوست منبع نیازمندی محصول است. متن‌های نقش‌دهی و دستور اجرای عامل در سند، مجوز مستقل برای تغییر محیط، انتشار یا اتصال حساب محسوب نشده‌اند. اولویت اجرای کار از درخواست مستقیم کاربر گرفته شده است.

## کاتالوگ A تا L

منبع داده: `apps/api/src/seed/catalog.ts`. کاتالوگ در تمام دسته‌ها قابل کشف است و `status`، سازمان، workflow، مدارک، مراحل، فرم نسخه‌دار، صحت هزینه/تماس و تاریخ بررسی را از API می‌گیرد. تعدادی از خدمات مرتبط در یک خدمت جامع گروه‌بندی شده‌اند؛ مانند «پروانه و شهرسازی» که انواع پرونده ملکی را پوشش می‌دهد. هیچ خدمت اتصال‌نیافته به‌عنوان اتصال رسمی معرفی نمی‌شود.

## مرزهای معماری آینده

- درگاه سازمانی: adapter مستقل به‌ازای سازمان با نسخه قرارداد، timeout، retry محدود، outbox و بررسی وضعیت؛ هیچ تغییر وضعیت بدون نتیجه معتبر انجام نشود.
- مالی: `payment_intents`, `payment_transactions`, `receipts`, `webhook_events` با شناسه یکتا، امضای provider و reconciliation؛ به‌طور پیش‌فرض غیرفعال.
- نان: `bakery_partners`, `capacity_slots`, `bread_orders`, `bread_order_history`؛ قفل سطر ظرفیت داخل تراکنش برای جلوگیری از overbooking. فعال‌سازی فقط پس از قرارداد.
- محتوا: منابع نسخه‌دار، صحت‌سنجی تماس/هزینه/مکان، تأیید دو مرحله‌ای و انقضا؛ داده ثبت‌شده تا تأیید عمومی نشود.
- چندشهر: کلید `city_id` و مرز سازمان در schema موجود است؛ routing tenant و تمام query guardهای چندشهر باید قبل از فعال‌سازی شهر دوم تکمیل و تست شوند.
- تحلیل: سنجه‌های تجمیعی بدون متن خصوصی؛ انتشار Open Data فقط پس از ناشناس‌سازی و مجوز. پیش‌بینی فقط بر پایه داده معتبر.
- عملیات: queue/outbox، SLA/escalation، audit قابل نگه‌داری و پایش؛ قرارداد B2G/B2B و صورت‌حساب در فاز تجاری، بدون تبلیغات مزاحم یا فروش اطلاعات شخصی.

## ترتیب تحویل

P0: چرخه شهروند/کارشناس، ثبت یکتا، مجوز رکورد و اعلان. P1: تکمیل پنل مرکزی و CMS، نقشه، دستیار مستند، شرکای روزمره. P2: پیامک و احراز هویت/درگاه/سازمان‌ها، SLA و قرارداد. P3: چندشهر، تحلیل بین‌سازمانی، SDK و Open Data مجاز. برای هر اتصال بیرونی، کلید، قرارداد و محیط تست معتبر پیش‌نیاز است.
