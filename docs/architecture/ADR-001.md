# ADR-001 — معماری پایه «تربت من»

- **وضعیت:** پذیرفته‌شده
- **تاریخ:** ۱۴۰۵/۰۸/۲۸ (2026-11-19)
- **تصمیم‌گیرنده:** تیم فنی دیجیرال

## زمینه

مخزن خالی بود. مسترپرامپت معماری monorepo ماژولار با Next.js، NestJS، PostgreSQL و Expo پیشنهاد کرده و اجازه داده تصمیم نهایی با ADR ثبت شود. محدودیت‌های محیط توسعه در لحظه شروع:

- Node 24، pnpm 9 نصب است؛ Docker نصب است ولی daemon در حال اجرا نیست؛ PostgreSQL محلی نصب نیست.
- کلید هیچ سرویس AI، پیامک، نقشه یا درگاه پرداختی در دسترس نیست.
- مخاطب اصلی با گوشی اندرویدی اقتصادی و اینترنت کند وارد می‌شود.

## تصمیم‌ها

| حوزه | انتخاب | دلیل |
|---|---|---|
| ساختار مخزن | pnpm workspaces (monorepo) | اشتراک قرارداد API، توکن‌های طراحی و ابزار فارسی بین اپ‌ها |
| API | **Fastify 5 + TypeScript + Zod** به‌جای NestJS | سبک‌تر، شروع سریع، اعتبارسنجی schema-first؛ OpenAPI مستقیماً از همان Zod تولید می‌شود؛ تست با `inject` بدون شبکه |
| پایگاه داده | **PostgreSQL** با **Drizzle ORM** و migration نسخه‌دار SQL | type-safe، migrationهای خوانا، بدون runtime سنگین |
| PostgreSQL در توسعه | **PGlite** (PostgreSQL واقعی کامپایل‌شده به WASM) وقتی `DATABASE_URL` تنظیم نشده | راه‌اندازی بدون Docker؛ همان SQL و همان migrationها؛ تست‌ها روی دیتابیس واقعیِ درون‌حافظه |
| PostgreSQL در تولید | `pg` با `DATABASE_URL` (Docker Compose در `infra/`) | — |
| اپ شهروندی | **Vite + React 19 + Tailwind 4 + PWA** به‌جای Next.js | اپ پشت ورود است و به SSR/SEO نیاز ندارد؛ باندل کوچک‌تر برای گوشی ضعیف؛ استقرار استاتیک ساده؛ کش آفلاین با Service Worker |
| پنل سازمانی | Vite + React جداگانه (`apps/admin-web`) | جداسازی باندل و نشست مدیریتی از شهروند |
| نشست وب | کوکی HttpOnly + SameSite=Lax + کنترل Origin روی درخواست‌های تغییردهنده؛ توکن opaque با hash در DB؛ چرخش توکن | قابل ابطال، بدون JWT طولانی‌عمر |
| نشست شهروند/مدیر | دو کوکی جدا (`tm_sid` و `tm_asid`) و دو مسیر auth | ورود مدیر نشست شهروند را بازنویسی نمی‌کند؛ اصل کمترین دسترسی |
| فایل | درایور ذخیره‌سازی خصوصی محلی + URL امضاشده کوتاه‌عمر (HMAC)؛ رابط آماده برای S3 | بدون سرویس بیرونی قابل اجراست |
| AI | لایه انتزاع provider: `rules` (قواعد کلیدواژه فارسی، همیشه فعال) و `anthropic` (فقط با `ANTHROPIC_API_KEY`) | قطع AI مانع ثبت نمی‌شود؛ هیچ پاسخ AI جعل نمی‌شود |
| نقشه | Leaflet + کاشی قابل تنظیم (`VITE_MAP_TILE_URL`) | پیش‌فرض OSM فقط برای توسعه؛ در تولید provider دارای مجوز |
| فونت | Vazirmatn (OFL) به‌صورت self-hosted | بدون وابستگی به CDN خارجی |
| موبایل بومی | Expo در فاز بعد؛ PWA قابل نصب در فاز ۱ | تمرکز بر کامل‌شدن چرخه اصلی |
| تست | Vitest (واحد/یکپارچه روی PGlite) + Playwright (E2E روی Edge/Chrome نصب‌شده) | بدون دانلود مرورگر اضافه |

## پیامدها

- اگر بعداً SSR لازم شد (مثلاً صفحات عمومی اخبار برای SEO)، می‌توان یک اپ Next.js جدا برای محتوای عمومی اضافه کرد؛ قرارداد API تغییری نمی‌کند.
- PostGIS در فاز ۱ استفاده نشده؛ مختصات به‌صورت `double precision` با ایندکس ذخیره و فاصله با فرمول haversine محاسبه می‌شود. با فعال‌شدن نقشه سازمانی (فاز ۲/۳) migration به `geography(Point)` انجام می‌شود.
- PGlite تک‌اتصالی است؛ فقط برای توسعه و تست. محیط آزمایشی عمومی و تولید باید PostgreSQL واقعی داشته باشند.
